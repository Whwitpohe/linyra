# Linyra

**仿 JetBrains（WebStorm）Git 日志的多仓库 Git 管理工具。**

工作区内所有仓库合并为一条日志，旁边是分支面板、提交详情、变更文件和原生 Diff；
提交、推送、更新、签出、合并、变基等日常操作直接从对应的行上跨仓库完成。

[English](https://github.com/Whwitpohe/linyra/blob/main/README.md) · [安装扩展](https://marketplace.visualstudio.com/items?itemName=whwitpohe.linyra) · [Open VSX](https://open-vsx.org/extension/whwitpohe/linyra) · [下载 VSIX](https://github.com/Whwitpohe/linyra/releases) · [更新日志](https://github.com/Whwitpohe/linyra/blob/main/CHANGELOG.md) · [反馈问题](https://github.com/Whwitpohe/linyra/issues)

一个需求改了前端、API、公共库和文档？搜索一次，就能看到所选仓库里的相关提交。
沿着真实分支图追踪合并，阅读完整提交信息，再用 VS Code 原生 Diff 核对每个文件；
之后一步完成所有仓库的提交、推送和更新，每个操作都在各自的仓库里执行。

![多选分支和作者，切换日期／拓扑排序，并折叠和展开线性历史](https://raw.githubusercontent.com/Whwitpohe/linyra/main/media/v1.5.0/feature-branches.gif)

演示使用六个中性的示例仓库和真实 Git 提交，画面为 1.5.0 的样子；从 1.7.0 起，每行还会显示作者头像圆点、
分支标签和“更改”列。静态图片均可打开查看原始分辨率。

## 1.7.0 新增

- **像 GitLens 提交图一样搜索：**`author:`、`file:`、`change:`、`after:`、`ref:`、`repo:` 等运算符，
  每个都转换成 `git log` 参数；输入框下方的弹窗列出全部运算符。
- **更丰富的日志：**作者圆点与头像、可点击的分支标签、悬停卡片、“更改”列、列标题、行末按钮，
  以及最上方的“未提交的更改”汇总行。
- **分支详情：**点击分支，查看上游状态、合并目标及预测的冲突、后续步骤，以及其它仓库里的同名分支。
- **更多跨仓库操作：**“推送…”会推送所有有待推送提交的分支，无论是否签出，被改写过的分支以租约方式强制推送；
  “更新项目”同时快进只落后于上游的分支；新增“跨仓库打标签…”、“跨仓库运行 Git 命令…”和“发版…”。
- **仓库树里看得到仓库状态：**每个分支的 ↓ 和 ↑、未提交标记、中断的合并或变基（解决、继续、中止）、工作树，以及智能签出。
- **Linyra AI，默认关闭：**接入你自己的 OpenAI 兼容、Anthropic 或 Gemini 模型，用来解释、审查、写提交信息和发版说明、解决冲突。
- **洞察：**可视化历史、文件与提交的矩形树图，以及仓库健康检查。
- **在你操作的地方提问：**选项弹在你点击的按钮下方，而不是窗口顶部；点击弹窗以外的任何地方即关闭。

## 安装与开始

在 Marketplace 搜索发布者 **whwitpohe** 的 **Linyra**，或执行：

```sh
code --install-extension whwitpohe.linyra
```

打开包含 Git 仓库的目录或多根工作区，执行命令 **Linyra: 打开合并日志**，
或点击底部 **Linyra** 标签。VS Code Git 已打开的仓库和工作区内发现的仓库会一起显示。

默认范围是**最近 24 小时、全部分支**。要找更早的提交，先把时间改为**全部时间**；
左侧仓库复选框可限制查看范围。Cursor、VSCodium、Windsurf 等使用 Open VSX 的编辑器，可从
[Open VSX](https://open-vsx.org/extension/whwitpohe/linyra) 安装，或从 [GitHub Releases](https://github.com/Whwitpohe/linyra/releases) 下载 VSIX。

## 一次搜索，串起多个仓库的改动

输入需求编号、关键词或提交信息，各仓库结果集中展示，左侧色带标明所属仓库。
选择提交后，右侧同步显示更改文件；点击文件，在上方原生编辑器里查看差异。

![完整工作区：上方原生 Diff，下方多仓库日志、真实分支轨道与更改文件](https://raw.githubusercontent.com/Whwitpohe/linyra/main/media/v1.5.0/screenshot-log.png)

- **搜索语法，由 Git 执行。**普通文字搜索提交信息；运算符进一步缩小范围，每个都转换成 `git log` 自己的参数：
  `message:` 与 `-message:`、`author:`（`@me`）、`committer:`、`commit:`、`file:`、`change:`（新增或删除的某一行）、
  `type:merge`／`type:tip`／`is:wip`、`after:`／`before:`、`ref:`（分支、标签或范围，如 `ref:main..feature`），
  以及 Linyra 的 `repo:`。输入框下方的弹窗列出每个运算符和示例，输入时提示作者、分支、标签和仓库。
  旁边有区分大小写、全字匹配、正则和全部匹配；↑／↓ 调出最近的搜索。
- **哈希定位。**完整哈希或至少七位十六进制前缀可直接定位提交，`sha:abcd` 支持至少四位前缀。
  哈希定位在所选仓库内暂时忽略其他筛选，清空后恢复之前条件。
- **作者、分支都能搜索多选。**“我”读取各仓库配置的邮箱。
  多分支取历史并集，共同提交只显示一次；清空分支选择恢复全部本地／远程分支。
  不含所选分支的仓库会跳过，并显示数量。
- **路径与日期。**路径支持相对于各仓库根目录的文件、文件夹或通配符；
  日期可选最近 24 小时、7 天、30 天、全部时间和自定义范围。
- **真实分叉与合并。**图中彩色轨道连接同一仓库内的真实父提交。
  “图”列的菜单可按提交日期或**按分支结构**（拓扑）排序，并折叠长线性历史，保留分支头、标签、分叉和合并。

**每一行显示什么。**仓库颜色的色条；作者圆点——用仓库颜色圈起的首字母（你的提交圈更粗），
或者从仓库自己的托管平台取到的作者头像；标题和**分支标签**——同一提交上的分支和远程分支合成一个标签，
当前签出的分支加粗并带 ↑／↓；作者、**更改**列（文件数和行数，可显示为数字、方块或条形）和日期。
**列标题**可以调整和隐藏列，设置“图”的排序和日期格式。鼠标停留会打开**悬停卡片**，显示提交信息和统计；
鼠标所在的行，当前签出的提交提供**撤销提交…**和**编辑提交信息…**，每一行都有 **⋯**（即该行的右键菜单）。
勾选的仓库有未提交的工作时，最新提交上方会多出一行**未提交的更改**：点击即可查看这些文件。

**演示步骤：**同时选择 `main` 与 `feature/saved-cards`，切换日期／拓扑排序，折叠并展开线性历史，
再多选作者。真实分叉、合并和分支头保持可见；默认仍是全部本地／远程分支和全部作者。

**不用重设筛选，也能定位旧提交。**粘贴哈希，即使时间选着“最近 24 小时”，仍能找到三个月前的提交；
清空哈希后恢复之前的日志。

![粘贴短哈希定位旧提交，清空后恢复原筛选](https://raw.githubusercontent.com/Whwitpohe/linyra/main/media/v1.5.0/feature-hash-lookup.gif)

## 看清完整提交信息

提交详情的样式与 VS Code 的面板一致：标题、原样保留的正文，然后是仓库、可复制的哈希、作者、时间、
父提交链接（点击即选中该父提交）和分支标签。当前签出分支的标签以 **HEAD** 开头；
下方列出的分支只包含标签里没有的那些。

![查看完整提交与彩色引用，调整或隐藏说明区域，并搜索更改文件](https://raw.githubusercontent.com/Whwitpohe/linyra/main/media/v1.5.0/feature-commit-review.gif)

**演示步骤：**查看 HEAD／本地分支／远程分支／标签的图标和颜色，展开包含分支，隐藏并恢复说明，
拖动分隔线，再把更改文件筛到 `PaymentStep`。

拖动文件列表和提交信息之间的分隔线调整高度，小箭头可隐藏／恢复说明，大小和显隐状态都会记住。
更改区工具栏保留**全部文件／更改文件**、展开／折叠、清除选择及提交操作菜单。
更改的文件在各处显示一致：文件名用 Git 状态色（删除的加删除线）、重命名的旧名称、增删行数和状态字母。

文件搜索支持名称、完整路径和重命名前路径；Enter 打开首个匹配，Escape 清空搜索。
文件树的按键与 VS Code 自己的树一致，直接输入文件名即可跳过去。

## 一眼看清一个分支

在日志行或提交详情里点击分支标签（或执行**显示分支详情**），更改区会显示该分支的**分支详情**：

- **上游：**已同步、待推送、待拉取、已分叉（拉取或强制推送…）、远程已删除（删除分支…或发布），或尚未发布；旁边的铅笔可更改上游。
- **合并到：**还有哪些提交不在合并目标上、落后多少，以及合并会不会冲突——用 `git merge-tree` 预测，
  不写入仓库（需要 Git 2.38+）。已合并的分支可以放心删除。
- **后续步骤：**总有可做的事——切换、签出、获取、新建分支…、推送…、查看历史、比较…，或已签出该分支的工作树。
- **所有仓库：**按需读取，列出每个勾选仓库里的同名分支（已签出、↑ ↓、已分叉、远程已删除），
  并可执行“全部签出…”、“推送…”和“更新项目…”。

## 在多个仓库里比较两条分支

从日志工具栏或 **Linyra: 比较分支** 打开比较面板。
只需选择一次左右分支，就能查看所选仓库中各自的差异，并明确列出缺少分支的仓库。

![切换文件／提交、展开提交文件、选择仓库、交换分支并调整左右大小](https://raw.githubusercontent.com/Whwitpohe/linyra/main/media/v1.5.0/feature-compare.gif)

**演示步骤：**发布分支和主分支各有独立改动；切换“文件／提交”，展开提交的文件，选择另一仓库，
左右交换并调整区域大小。三个区域保持在稳定的同一视图中，原有操作入口继续保留。

**文件／提交**模式、左右交换、刷新、分支搜索、收藏和最近使用都可直接操作。
左右侧还各自保留显示模式、相同内容过滤、展开／折叠、加载更多和右键菜单。
点击文件查看两条分支当前版本的原生 Diff；“自分叉以来的更改”用于核对此侧带来的内容。

- **每侧可以填多个分支名。**按顺序列出（如 `develop, develop-k` ↔ `main, master`，或各仓库的“默认分支”），
  每个仓库用它有的第一个，仓库行会写明实际用的是哪个（如 `develop-k → main`）。在分支选择器里勾选多个，序号就是优先级，用 ∧ ∨ 调整。
- **合并前就知道会不会冲突。**每个仓库都在内存里试合并一次（`git merge-tree`，需要 git 2.38+，不往仓库写任何东西）：
  仓库行显示 ✓ 或会冲突的文件数，冲突文件单独标出，“只看冲突文件”只列这些文件，“预览合并结果”打开带冲突标记的合并后文件。
- 列表顶部的**全部仓库**把所有仓库的文件或提交合在一棵树里看；按住 Ctrl/Shift 点击可以只选几个仓库合在一起看（合并和发版说明也只针对这几个）。
  仓库列表先出来，每行的冲突检查随后逐个补上。两侧都有筛选框；提交行显示日期。
- **直接操作：**多选（Ctrl/Shift 点击）某一侧的提交后“拣选”；“把 ◀ 合并进 ▶…”列出能干净合并的仓库供勾选（右键单个仓库只合并那一个）；
  “把 ◀ 的提交复制为发版说明”按仓库生成 Markdown。合并按分支框的方向进行：▶ 已签出时执行 `git merge`；
  没签出时不切换分支，直接合进 ▶，不动你的工作区。
- **发版…**（日志的 ⋯ 菜单）把 ◀ 合并进 ▶ 作为一次发版，逐步确认：发版说明、合并、
  在 ▶ 上打带该仓库说明的标签，然后推送。

日志／更改区与分支比较都支持左右或上下布局、拖动分隔线、明确的显示／隐藏按钮。
点击标题或右侧空白不会折叠整片视图；文件夹和提交树由小箭头或键盘操作展开。
“在编辑区独立打开更改”还可打开单独可移动的更改标签。

## 一次处理所有仓库

- **推送…**（Ctrl+Shift+K）在一个清单里列出每个勾选仓库待推送的提交：先是签出的分支，
  再是其它领先于上游的本地分支——比如把 develop 合并进了未签出的 master——单独放在一个标题下。
  每个仓库直接推送勾选的分支，不切换分支。已推送的提交被改写过的分支单独列出、默认不勾选；
  勾选后会以最近一次获取的提交为租约强制推送，推送前会确认远程将丢失哪些提交。
  main、master 和 VS Code 的 `git.branchProtection` 保护的分支永远不会被强制推送。
- **更新项目**（Ctrl+T）先获取，再把每个签出的分支合并、变基或快进到上游——每次询问，
  或在方式旁点图钉记住（`linyra.updateMethod`）；从不自动储藏。其它只落后于上游的本地分支也会一并快进，不需要签出。
- **跨仓库分支操作…**（Ctrl+Shift+`）在所有仓库中签出、新建或合并同名分支。
  本地改动挡路时，**智能签出**会先储藏这些改动，签出后再放回去。
- **跨仓库打标签…**给每个签出的提交打标签（填写说明即为附注标签），可选择一并推送。
  **跨仓库运行 Git 命令…**执行一条命令（从不经过 shell），显示每个仓库的输出；可能写入的命令会先确认。
  **在所有仓库中中止…**结束多个仓库里中断的合并或变基。
- 完成后用一份报告说明哪些完成了、哪些已经是最新、哪些中断了，以及跳过的原因。

## 仓库树

日志左侧的树像 JetBrains 的分支面板一样，把每个仓库的**本地**、**远程**、**标签**、**储藏**和**工作树**归在一起。
可以搜索仓库名或分支名；点击分支只会把日志筛到该分支，不会签出。

- **状态一目了然：**每个仓库显示当前分支，并用 VS Code 的 `*` `+` `!` 标出未提交的工作；
  与其它仓库不在同一分支时会特别标出；↓（待拉取，蓝色）和 ↑（待推送，绿色）。
  每个本地分支也显示自己相对上游的 ↓ 和 ↑（以最近一次获取为准）。
- **中断的合并、变基、拣选、还原或补丁**会显示为徽标（“2 个冲突”），并在仓库下方多出一行：
  **解决冲突…**（VS Code 的合并编辑器）、**继续**、**中止…**、**在所有仓库中中止…**。
- **右键**可签出、新建、比较、重命名、合并、变基、更改上游、新建工作树、获取、拉取、推送和删除；
  标签可签出（分离 HEAD）、推送和删除；储藏可应用、弹出、删除或查看更改；工作树可在新窗口中打开、
  在文件资源管理器中显示、复制路径和移除。收藏的分支排在最前；**取消勾选**、**永久排除（写入设置）**
  和保存的**仓库组**决定日志显示哪些仓库。

![按分支名搜索仓库树：每个仓库展开为本地和远程分支](https://raw.githubusercontent.com/Whwitpohe/linyra/main/media/v1.5.0/screenshot-branch-sidebar.png)

## 在侧边栏提交

活动栏的 Linyra 图标打开提交侧边栏，仿 JetBrains 的提交窗口：所有勾选仓库的“更改”和“未受版本控制的文件”，
用原生树显示（沿用你的文件图标主题），每行带勾选框；一条提交信息、“修改上次提交”、Sign-off、“作者…”、
“提交信息历史”（Ctrl+M），以及“提交”（Ctrl+Enter）或“提交并推送…”（Ctrl+Alt+K）。
每个有勾选文件的仓库各提交一次，只提交勾选的文件，其他已暂存的内容保持暂存。

- 提交信息从 git 的 `commit.template` 开始；某行超过 72 个字符或标题后缺少空行时给出提示，但不会阻止提交。
- 新文件勾选后随提交一起加入版本控制，也可以用“加入版本控制”（Ctrl+Alt+A）立即加入，或用“加入 .gitignore”排除。
- 三个命令互不混淆：“放弃更改”（Ctrl+Alt+Z）把已跟踪的文件恢复到上次提交，不会删除新文件；
  “移出版本控制”把刚加入的文件移出、文件保留；“删除…”（Delete）把新文件从磁盘删除。
- 在仓库行上可以“储藏更改…”（可选是否包含新文件）和“应用补丁…”（来自文件或剪贴板；
  作为更改应用，必要时提供三方合并，或把邮件格式的补丁作为提交应用）。
- 单击文件（或 Ctrl+D）查看差异；可按仓库、按目录分组，或都不分组。

## Linyra AI（可选）

默认关闭：`linyra.ai.enabled` 关闭时不会向任何地方发送内容，AI 菜单项也不显示。
**Linyra: 配置 AI…** 打开 Linyra AI 页面：可添加 OpenAI 及任何 OpenAI 兼容服务（Ollama、LM Studio）、
Anthropic 和 Gemini 的配置，每个配置有自己的模型、思考程度和“测试连接”。
API 密钥保存在 VS Code 的机密存储中，并且只用于当初输入时的地址。

- **解释**提交、未提交的更改、未推送的提交、与当前分支的差别或冲突；**审查**提交；根据提交或分支比较**写发版说明**。
- 在提交侧边栏**用 AI 生成提交信息**，遵循你的 `linyra.ai.commitMessageInstructions`；✨ 也能为储藏起名。
- **用 AI 解决冲突…**逐个文件给出解决方案，写入前先确认。
- 搜索框里的 ✨ 把一句问题转成运算符搜索；日志标题栏的**问 AI…**用文字回答，只读步骤直接执行，
  会写入仓库的步骤先在一个确认框里列出。
- `linyra.ai.exclude` 让锁文件、构建产物和密钥类文件不进入任何提示词；`linyra.ai.maxPromptTokens` 在请求过大时先询问。

## 洞察

**Linyra: 洞察**（或对文件、文件夹执行**可视化历史**）打开一个标签页，范围可以是勾选的仓库、其中一个仓库或该路径：

- **可视化历史：**每个提交一个气泡，大小表示改动行数；每位作者一行，按仓库或作者着色；点击即在日志中显示该提交。
- **文件**与**提交：**已跟踪文件的矩形树图，按文件大小或范围内修改它的提交数绘制，热点文件一目了然。
- **健康：**每个仓库一行——commit-graph、对象、未跟踪缓存、文件系统监视器、大量文件、维护——
  每项都说明含义并给出建议。**优化所选…**在一个确认框里列出所有要执行的命令，未经确认不写入任何内容。

## 日常使用的其他入口

| 功能 | 入口与用途 |
| --- | --- |
| **文件历史** | 在资源管理器、编辑器／标签或更改区右键文件，或右键文件夹查看**文件夹历史**。日志显示该路径跟随重命名的历史：每行显示提交对该文件的改动（状态字母和行数），未提交的改动排在最上面；行上可**在此版本查看 Blame**。暂时放开搜索、作者和日期限制，退出时恢复。 |
| **合并查看更改** | Ctrl/⌘ 或 Shift 多选提交，支持跨仓库。同一文件汇总展示；可分离时只展示所选提交带来的改动，无法分离的重叠改动会提示。不会改写提交历史。 |
| **未提交改动** | 日志顶部“提交／未提交”切换：每个有改动的仓库一行，显示按类型统计的文件、分支及其 ↑／↓、最后修改时间。通过明确命令暂存、取消暂存、丢弃和提交，接入 VS Code Git。 |
| **提交操作** | 右键提交：拣选（可一次拣选多个选中的提交，从最旧开始）、还原、将当前分支重置到此处、签出此提交、在此处新建分支或标签；“与工作区比较…”、“生成补丁…”（选中的提交，保存到文件或复制到剪贴板）和“推送到此提交为止…”（把当前分支推送到该提交为止，之后的提交留在本地）。当前签出的提交还可以撤销提交、编辑提交信息。 |
| **仓库组** | 保存当前仓库选择，之后一键恢复；通过工作区 `linyra.profiles` 设置共享。 |
| **获取／拉取** | 按需获取，查看领先／落后数量，筛出落后仓库；批量拉取使用快进检查。 |
| **行归属与当前文件** | 原生 Diff／历史版本编辑器显示行归属；“打开文件”跳到工作区当前文件的相同行。 |
| **复制与远程链接** | 提交和文件右键菜单提供复制及支持的 Git 托管平台链接。 |

## 键盘、主题与语言

| `Ctrl+Shift+K` | 推送… |
| ``Ctrl+Shift+` `` | 跨仓库分支操作… |

Linyra 的提问——单选、多选清单或输入名称——会弹在你点击的按钮下方或右键的位置，支持 ↑ ↓ Enter Esc；
点击弹窗以外的任何地方即关闭。从命令面板执行时仍使用 VS Code 的选择框；需要确认的操作仍使用 VS Code 的对话框。

界面颜色和字体跟随 VS Code，支持浅色、深色及两种高对比度主题。
语言随编辑器显示语言切换，支持英文和简体中文，其他语言回退为英文。

## 设置与运行要求

需要 **VS Code 1.85+** 和 **Git**（冲突预测需要 2.38+）。Git 路径依次采用 `git.path`、VS Code Git 找到的程序或 PATH 中的 Git。
查看历史、搜索与折叠不会写仓库；Git 操作只在明确选择对应命令时执行。

| 设置 | 默认值 | 用途 |
| --- | --- | --- |
| `linyra.pageSize` | `200` | 每仓库每页读取提交数量 |
| `linyra.maxConcurrency` | `16` | Git 最大并发数 |
| `linyra.scanDepth` | `2` | 工作区目录内的仓库发现深度 |
| `linyra.excludeRepos` | `[]` | 排除的仓库名／路径模式 |
| `linyra.profiles` | `{}` | 命名的仓库选择配置 |
| `linyra.blame` | `true` | 在 Diff 与历史版本中显示行归属 |
| `linyra.updateMethod` | `ask` | 更新项目如何并入新提交：每次询问、合并、变基或仅快进 |
| `linyra.avatars` | `remote` | 作者头像：`off`、`remote`（只请求你的远程所在的服务器）、`remote+gravatar` |
| `linyra.avatarHosts` | `{}` | 自建远程服务器的类型（`gitlab`、`github`） |
| `linyra.avatarUrlTemplate` | `""` | 自己的头像服务（只能在用户设置中设置） |
| `linyra.ai.enabled` | `false` | 打开 Linyra AI；关闭时不发送任何内容 |
| `linyra.ai.profiles` / `linyra.ai.activeProfile` | `[]` / `""` | AI 连接及当前使用的配置，由 Linyra AI 页面写入（密钥在机密存储中） |
| `linyra.ai.commitMessageInstructions` | `""` | AI 生成提交信息时遵循的自定义要求 |
| `linyra.ai.exclude` | 锁文件、构建产物、密钥类文件 | AI 提示词中排除的文件 |
| `linyra.ai.maxPromptTokens` | `50000` | 请求超过此大小时先询问（`0` 表示从不询问） |

从 1.4.2 开始，设置只使用 **`linyra.*`**，不读取或迁移旧 `polylog.*` 设置。
需要自定义时使用新名称配置；现有配置文件保持原样。

![VS Code 原生设置页以 Linyra 自己的名称列出各项设置](https://raw.githubusercontent.com/Whwitpohe/linyra/main/media/v1.5.0/feature-settings.png)

筛选条件交给 Git，读取结果分页合并；不维护持久化历史索引或数据库，不后台获取远程更新。
输入筛选有防抖，新查询会取消被替代的 Git 读取。作者头像只向你的仓库远程所在的服务器请求，
只为屏幕上的行请求，结果只保存在内存中，窗口重新加载后清空。

## 从 Polylog 切换

Linyra 基于 **lntvan166** 创建的 [Polylog](https://github.com/lntvan166/polylog) 独立维护，
扩展 ID 为 **`whwitpohe.linyra`**。设置、命令、视图及历史版本 URI 均使用独立的 `linyra` 命名空间，
可与 `lntvan166.polylog-git` 共存。自定义快捷键需使用 `linyra.*` 命令 ID。
旧版 Linyra 保存的筛选和面板大小会在自身私有存储内迁移；原版扩展的设置及私有存储保持独立。

原 `v1.4.0` GitHub Release 保留历史 Polylog 安装包，后续 Linyra 版本使用与源码匹配的新标签和 VSIX 名称。
