# Linyra Insights — Visual History, Files, Commits and Repository Health

Reference: GitLens's Visual History and its Repository Health page (behavior only). Adapted to
Linyra's rules: every chart spans the ticked repositories at once (each repository in its own
Log color), nothing is indexed or cached between sessions, every read is one git process per
repository pushed down into git's own flags, and a repository is written only after a click and
a confirmation that names the exact command.

## Where

One editor tab, **Linyra Insights**, opened by:

- **Linyra: Insights** (`linyra.insights`): the palette, and the Log's ⋯ menu (the coordinating
  session adds ToolbarAction `insights`).
- **Visual History** (`linyra.visualHistory`): the Explorer's right-click on a file or folder, an
  editor tab's right-click, and the Changes view's file and folder rows (`webview/context`,
  `webviewSection == 'changesRow'`). It opens the tab on Visual History scoped to that path.

Reopening the command reveals the open tab (one at a time), with the scope it was asked for.

## Header

`[Visual History] [Files] [Commits] [Health]` — a tab list (←/→, Home/End move; Enter or Space shows).

Below it one row of controls:

- **Scope**: a select. "Ticked repositories (N)" (the Repo List's ticks, as the Log), each ticked
  repository by name, and — when opened on one — the file or folder (`acme-web › src/client.ts`).
  Health uses the scope's repositories (a path scope means its repository).
- **Range** (Visual History and Commits only): 1 week · 4 weeks · 3 months · 1 year · All, a
  radio group. Default 3 months. Git's `--since` (committer date, as the Log's date filter).
- **Color by** (Visual History only): Repository · Author.
- **Refresh**: reads the shown tab again.

The tab, range and color are remembered (globalState). The scope is not: a new tab starts from
the ticked repositories unless a command named a path.

## Reads — when and how many

A tab reads only when it is shown, and only what it shows. Its answer stays in memory while the
tab is open (what is on screen, as the Log keeps its rows): switching tabs back shows it again
without git, and a scope of fewer repositories (one of the ticked ones) shows what was read of
them. It is read again when a path or the range changes, on Refresh, when a repository in it
reports moved refs (the Log's `onDidChangeRefs`: a commit, checkout, pull — only that repository),
and after a Health write (only the written ones). Closing the tab drops it.

Overlapping requests (`src/insights/reads.ts`, unit tested): a newer request wins and an older one
never posts over it; a second request for the same answer waits for the read in flight instead of
starting another; a repository whose refs move while it is read is not stored from that read and
is read again; results are stored as each repository lands, so a read stopped (the tab hidden or
left, a new path or range) loses only what was still running. Tabs are activated by Enter or Space
(arrows only move the focus) and the Range waits 300 ms after the last arrow, so walking past a
choice reads nothing. The webview is retained while hidden: the chosen file, the ticks and the
keyboard's place survive.

| Tab | Per repository in scope | Parsed |
|---|---|---|
| Visual History | 1 × `git log HEAD --no-merges --since=… --max-count=5000 --numstat --format=%x1e%H%x1f%ct%x1f%aN%x1f%aE%x1f%s [-- path]` | each commit's lines added + deleted, files |
| Files | 1 × `git ls-tree -r -l -z HEAD [-- path]` | blob sizes per path |
| Commits | 1 × `git log HEAD --no-merges --since=… --name-only -z --format= [-- path]` | commits per path |
| Health | 1 × `git count-objects -v` + 1 × `git config --get-regexp '^(core\.(untrackedcache\|fsmonitor)\|feature\.manyfiles\|maintenance\.(repo\|auto\|strategy))$'` | |

Health reads the rest from the git dir's files, with no process: the commit-graph (`objects/info/
commit-graph` or a split chain, as the slow-topo hint does) and the tracked-file count (the
index's 12-byte header: "DIRC", version, entry count). `maintenance.repo` lives in the global
config, which the same `git config` read includes.

`--numstat`, not `--shortstat`: shortstat's words are translated by git's gettext and cannot be
parsed under a Chinese locale. Merges are left out (`--no-merges`): their diff against the first
parent counts a whole branch's work twice. `%aN`/`%aE`: the repository's `.mailmap` joins an
author's names. Visual History stops at 5,000 commits per repository and says which repositories
were cut ("acme-web: the latest 5,000 commits only — narrow the range").

The integration suite asserts these counts with the Log's spawn log.

## Visual History

A bubble chart. Time runs along x (nice ticks: days, weeks, months, years, in the UI language);
each author is a row on y, labeled with the Log's author disc (initial, ring in the author's
color or, colored by repository, the repository they commit to most), the name and the count.
Most active author first. Rows are at least 28px; more rows scroll under a sticky axis.

One bubble per commit, area ∝ lines changed (radius √, clamped to 3…row/2; the domain stops at
the 95th percentile so one vendored import does not shrink everything else), filled with the
repository's Log accent (or the author's color) at partial opacity with a solid ring. Hover: the
commit's subject, short id, repository, author, date, +added −deleted, files. Click or Enter:
reveal it in the Log (`linyra.revealCommit { repoId, sha }`, LogView's `showCommit`).

Keyboard: the chart is one tab stop. ←/→ previous/next commit in time on the focused row, ↑/↓
the nearest commit on the row above/below, Home/End, Enter reveals. A visually hidden status
line announces the focused commit; the tooltip follows focus.

Above the chart: "N commits by M authors in K repositories · merges not shown"; a legend of the
repository (or author) colors.

## Files

A squarified treemap (Bruls, Huizing, van Wijk) of the tracked files at HEAD: repositories, then
folders, then files; area = file size. Files are colored by type: the extensions holding the
most bytes in scope get the `--vscode-charts-*` palette (the Log's accent tokens, which hold in
high contrast), the rest "Other" in the description color; a legend lists them with sizes.

The view shows one folder (at first the scope) and nests up to six levels inside it; tiles too small
to read draw no label, tiles under 2px are merged into their folder. A folder tile's header strip
names it. Click a folder (or Enter) to go into it; a breadcrumb goes back (Backspace too). Click a
file to select it: the strip below the map shows its path, size and buttons **Open File**,
**Visual History**. Keyboard: the map is one tab stop, arrows move between tiles of the shown
level (by geometry), Enter goes in or selects.

The host keeps the parsed tree for the open tab and sends one folder at a time, pruned to its
nested levels, at most 200 children per folder (the rest summed as "N smaller files") and 5,000 nodes in all, so a
200,000-file repository does not cross the webview boundary at once.

## Commits

The same treemap with area = commits touching each file in the range (files untouched are not
drawn). Heat: tiles are tinted by their count's rank — the top tenth in the conflict color, then
three steps toward the editor background — and every tile with room for a label names its count (a smaller one in its tooltip and to the keyboard), so heat is
never color alone. High contrast: tiles keep the theme's contrast border; the hottest get a
thicker one. The strip offers **Open File**, **Visual History** (that file, same range).

## Repository Health

One table over the scope's repositories:

| Column | Value | Recommendation |
|---|---|---|
| Commit-graph | Present / Missing | Missing and ≥ 1,000 objects: write one. Speeds `log --graph`, topological order, ahead/behind. |
| Objects | loose count · packs · pack size | ≥ 6,700 loose (git's `gc.auto`): run the loose-objects task. ≥ 50 packs (`gc.autoPackLimit`): incremental-repack. |
| Tracked files | the index's entry count | (feeds the three below) |
| Untracked cache | On / Off / On (feature.manyFiles) | ≥ 10,000 tracked files and off: turn on. `git status` stops rescanning unchanged folders. |
| File system monitor | On (built-in) / Hook / Off | ≥ 50,000 and off, on Windows and macOS: turn on (git runs a watcher daemon). Linux: not available. |
| Many files | On / Off | ≥ 100,000 and off: turn on (index v4, skipHash, untracked cache). Warns that older libgit2 and JGit cannot read a skipHash index. |
| Maintenance | Registered / Not registered | ≥ 10,000 files or ≥ 100 MB packs and not registered: suggests `git maintenance start` (it schedules the machine's task scheduler, so Linyra does not run it). |

Each column header explains itself (hover and the details). A row's suggestions count shows at
its end; selecting a row (click, ↑/↓, Enter) shows its details below: every check as a line with
the plain-language explanation, the recommendation and its button.

### Writes — only on a click, each confirmed

| Button | Runs | Confirmation names |
|---|---|---|
| Write Commit-Graph | `git commit-graph write --reachable` | the command, `.git/objects/info/commit-graph` |
| Run Maintenance… | a pick of tasks (commit-graph, loose-objects, incremental-repack, pack-refs, gc), then `git maintenance run --task=…` | the command and that it rewrites packs and objects, keeping every commit |
| Turn On / Turn Off | `git config --local <key> true\|false` | the command, `.git/config` |
| Optimize Selected… | each ticked row's recommended writes above (rows with any start ticked) | every repository and command, in one dialog |
| Copy Command (Maintenance) | nothing: copies `git -C "<root>" maintenance start` for a terminal | — |

A setting implied by another (the untracked cache under feature.manyFiles) and a monitor hook
(`core.fsmonitor` naming a program) have no button: turning them off is the other setting's, or
the hook's owner's, call. On Linux the monitor has no button (git's own is Windows and macOS only).

Writes run with `GIT_OPTIONAL_LOCKS=1` (as Write Commit-Graph from the slow-topo hint), two
repositories at a time, each repository's commands in order (stopping at the first failure),
through the Log's counted runner, under a progress notification. Failures name their repository
and command. Only the written repositories' health is read again (two processes each).

## Look

VS Code tokens only (no hex): `--vscode-charts-*` and the Log's `accent-*` classes, `--vscode-
editor-background`, `--vscode-foreground`, `--vscode-descriptionForeground`, list and focus
tokens, `--vscode-contrastBorder` / `--vscode-contrastActiveBorder` in high contrast. Correct in
light, dark, high-contrast dark and light. Narrow (≤ 520px): controls wrap, the author column
narrows to the disc, the Health table scrolls sideways with the repository column sticky.

## Code

Pure (no `vscode`, no DOM), unit tested:

- `src/insights/parse.ts` — the numstat log, `ls-tree -z`, `--name-only -z`, `count-objects -v`,
  `config --get-regexp`, the index header.
- `src/insights/range.ts` — ranges to `--since`, scopes to pathspecs, a path to its repository.
- `src/insights/bubbles.ts` — radius scale, time ticks, author rows, keyboard neighbors.
- `src/insights/treemap.ts` — the path tree, pruning, the squarified layout, extension ranking,
  heat ranks.
- `src/insights/health.ts` — effective config, thresholds, recommendations, the write plans and
  their confirmation text.

Host: `src/insights/panel.ts` (the WebviewPanel, reads, writes), `src/insights/protocol.ts`.
Webview: `src/webview/insights/` (`html.ts`, `main.ts`, `history.ts`, `treemap.ts`, `health.ts`,
`insights.css`). Bundle `out/insights.js` / `.css`.

Harness: `dev/harness/insights.html` with `insightsShim.ts` and mock data (`?tab=`, `?state=empty|
loading|error|many`), on `HARNESS_PORT=5212`.

## Tests

1. Unit: every pure module above.
2. Playwright (`dev/harness/tests/insights.spec.mjs`): each tab in the four themes and at 420px,
   keyboard paths, the messages a click posts, no console errors, screenshots looked at.
3. Integration (`src/integration/insights.itest.ts`): process counts per tab and per repository,
   nothing re-read on a tab switch, a commit makes it read again; Write Commit-Graph and a config
   toggle write exactly what the confirmation said, and nothing when it is declined.
