Linyra UI Map

Every part of the Linyra panel, with the name we'll both use for it. Say "Repo List row" or "Log header" and we mean the same thing.

Click any box, number or name to copy the name. Each red box is one named region, and its red number points to the name below. Boxes inside boxes are parts of a bigger region (the Filter bar sits inside the Log view). The Log and Compare each use one native surface; their headings are labels, not full-row collapse controls. The mocks scroll sideways on a narrow screen.

1Linyra panelThe "Linyra" tab in VS Code's bottom panel. Holds every Linyra view.
2Log viewThe merged history of every repository. Everything on its left side, down to the footer, belongs to it.
3Log headerOne row, as the JetBrains Log keeps it: the Commits | Uncommitted switch, the Filter bar, then the actions — show/hide changed files, repository grouping, Compare, Fetch All, Update Project… (⇣), Push… (⇡) and ⋯. It wraps onto a second row only when the Log is narrow. ⋯ holds Branches Across Repositories…, Tag Across Repositories…, Run Git Command Across Repositories…, Release… (and, while one is stopped, Abort in All Repositories…), the pull/profile items, the Uncommitted side bar, the Changes layout (automatic, side by side, stacked), the view options (Highlight My Commits, Highlight Current Branch, Show Hash Column) and Collapse/Expand Linear Branches.
4Repo ListThe tree of repositories on the Log's left, as the JetBrains Branches panel groups a multi-root project. Tick to choose which repositories the Log shows; ▸ opens a repository onto its Local, Remote and Tags branches. Today's name in the code is "Repositories pane".
5Repo search"Find repo or branch": narrows the Repo List by repository name, and finds branch names too (a repository found by a branch opens on the matches).
6All repositories rowTicks or unticks every repository; shows how many are picked.
6aProfile rowA saved group of repositories (linyra.profiles). Click: tick exactly them; highlighted while the ticks are that profile. ⚠ when some are not in this workspace. Right-click: Show, Update to Current Selection, Rename…, Delete. ⋯ → Switch Profile… does the same with the Repo List hidden.
6bSave as profile row"＋ Save as profile…": shown while the ticked repositories are neither All nor a profile. Click to name them. Right-click a repository for Profiles… (which profiles it is in).
7Sync badge↓ commits to pull, ↑ commits not pushed, as of the last fetch.
8Repo List rowOne repository: ▸, checkbox, color dot (same color as its band in the Commit list), name, then its branch with VS Code's * + ! for uncommitted work (a narrow list names only a branch the other ticked repositories are not on, as an icon), and a stopped merge, rebase, cherry-pick or revert as "⚠ merging · 2" (right-click: Resolve Conflicts…, Continue, Abort…, Abort in All Repositories…, Apply Patch…). Right-click for the Repo menu. Opened: its Local, Remote and Tags groups; a branch row filters the Log to it (never checks it out), ☆ marks a favorite, right-click holds the branch actions (tags: check out detached, push, delete); a checkout refused for local changes offers Smart Checkout. A Worktrees group lists the repository's linked worktrees: Open in New Window, Reveal, Copy Path, Remove Worktree….
9Filter barThe boxes above the commits. Every filter runs inside git.
10Search boxGitLens's search syntax, pushed into git log: plain words and message: (=:), -message:, author: (@:, @me), committer:, commit: (#:), file: (?:), change: (~:), type: (is:), after: (since:, >:), before: (until:, <:), ref: (^:) and Linyra's repo:. The Operator popup (55) lists them; ↑/↓ recall recent searches; Enter runs at once. Its toggles: Match Case, Whole Word, Regex, Match All (56) and ✨ (57). Hashes still jump straight to their commits.
11Author boxSearchable multi-select checklist, with the Me toggle and each repository's own identity.
12Path boxCommits that touched a file, folder or glob.
13Branch boxAll local and remote branches by default. Search and select several names; Git returns their union. A repository without any selected branch is skipped, not replaced with its current branch.
14Date range24 hours, 7 days, 30 days, all time, or custom.
15Refresh buttonReads every repository again.
16Commits | Uncommitted switchAt the top of the Log. Its badge counts the uncommitted files in the ticked repositories. Uncommitted shows one Uncommitted list row per repository with work (files, change meter, staged/new tags, when edited); clicking one shows its files in the Changes view. Right-click a row or the Changes view root for Commit…, Stage All, Unstage All and Discard All Changes; a file or folder there for Stage, Unstage and Discard. Several selected rows act together.
17Commit rowRepository strip (51), the real parent graph with Author discs (52), the subject, Branch pills (53), author and date. Resting the pointer opens the Commit hover card (54). Hovering a disc of a linear run shows its fold box; selection keeps real commit ids.
18Load moreThe next page of commits.
19Log footerThe selected date/topology order, branch-scope coverage, folded count and commit count.
20Changes viewIntegrated changed-file region with its own toolbar, file search and independent scrolling. It can also open as a movable editor tab.
21Commit detailsUnder its pane header (66): the title, the message body as written, then the facts in the secondary color — repository, hash, author, date (never broken mid-line), Parent links (66) and the branch pills. Drag its divider to resize; a click on the header folds it.
22Folder rowA folder, with how many changed files it holds.
23File rowA changed file, drawn the same in the Changes view, Compare's sides and File History: its name in the status color (struck through when deleted), a rename's old name and any note muted, + lines in the add color and − in the delete color whatever the status, then its letter in one column (A, M, D, R, C, T, U untracked). The Commit side bar draws the same letter and color as VS Code's file decoration. Click opens the diff.

27Uncommitted sideThe Log's Uncommitted tab (the Commit side bar, 43, shows the same work to commit): one Uncommitted row (62) per ticked repository with uncommitted work. Hover a row: ✓ Commit… on a repository (right-click it for Stage All, Unstage All and Discard All Changes); ↶ Discard and − Unstage on staged rows; ↶ Discard and + Stage on changes. Discard always asks first. Each file opens the diff Source Control would.
29All Files toggleChanges toolbar: switch all/changed files, clear a combined selection, expand/collapse all, copy commit data or open Changes independently.
30Staged groupAnd its sibling, the Changes group: what is staged and what is not, under each repository on the Uncommitted side. A file staged and changed again is in both.
28Linyra Compare tabA panel tab next to Linyra (⇄ in the Log toolbar, or the Command Palette): Repositories · Left · Right, side by side; a file opens its diff in the editor area above.
31Compare toolbarBranch pickers (a side may tick several names; their numbers are the order, ∧ ∨ change it; Default branch is each repository's origin/HEAD), swap, Files/Commits, refresh, shared-file filtering, Show Only Conflicts (pressed while on, with how many files would conflict), Merge ◀ into ▶… (a checklist; into ▶ itself, checked out or not, the working tree untouched where it is not), Copy ◀ Commits as Release Notes, layout, side visibility and Close. All original commands remain reachable.
32Branch pickerOpens under a branch box: a search box over Recent pairs, Favorites ★, Local and Remote, each name "in N repositories".
33Compare repository rowOne per ticked repository whose files differ: its Repo List color and name (commit counts in the tooltip), and its merge note: ✓ merges cleanly, or ⚠ and how many files would conflict (git merge-tree, in memory). With several names on a side, a second line says which ones it uses ("develop-k → main"). "no common history" or "git error" when it cannot be compared. All repositories, at the top when two or more differ, shows every one in one tree; Ctrl/Shift-click picks several for that tree (Merge and Release Notes then take just those). The merge note turns while its check runs: the list never waits for it. ▸ unfolds the changes committed on both sides. Selecting it fills Left and Right. Right-click: the repository menu.
34Left and Right viewsTwo resizable regions within one Compare surface. Folder/commit text selects a row; only the small arrow or a keyboard action folds it; Ctrl/Shift-click selects several (Cherry-Pick takes them all). Each has a filter box. Both sides retain display mode, shared-file filtering, expand/collapse, Show More and file/commit context menus; a conflicted file adds Preview Merge Result.
35On both duplicatesUnder a Repositories row (its ▸): each change committed on both sides (cherry-picked), with both commit ids.
36Missing a branchMissing repositories are listed separately. Its small arrow expands the names; the heading text and right-hand blank space do not.

43Commit side barThe Linyra icon in the Activity Bar, as the JetBrains Commit window: a native tree of every ticked repository's uncommitted work with a checkbox on each row (files carry your file icon theme's icons and Source Control's letters), and below it the Commit Message view. VS Code's own Activity Bar menu hides it.
44Commit toolbarThe view's title: how much is uncommitted, then Refresh, Rollback… (Ctrl+Alt+Z: the selected rows, else the checked files, after one prompt) and Collapse All. Its ⋯ menu: Group by Repository and Group by Directory (on or off), Commit Message History….
45Changes and Unversioned FilesTracked changes, checked by default; new files, unchecked until you check them, under an Unversioned Files that starts collapsed: checked, they are added with the commit; Add to VCS (Ctrl+Alt+A, or the + on the row) adds them now. Staged and unstaged halves of a file are one row: the commit takes the file as it is.
46CheckboxOn a list, repository or folder it checks everything under it. VS Code's checkboxes have no third state: a partly checked row says "2 of 5 files checked".
47Commit file rowClick (or Ctrl+D): the diff, last commit ↔ working tree. Hover: Open File and one of three, never alike: Rollback (a tracked change: back to the last commit), Remove from VCS (an added file: out of the index, kept on disk) or Delete (a new file: from the disk, Delete key). Right-click: Show Diff, Open File, Add to VCS, Add to .gitignore, Rollback…, Remove from VCS, Delete…, File History, Copy Path. A repository row adds Stash Changes…, Pull, Open Folder.
48AmendThe checked files join each repository's last commit, under the new message. With an empty box it brings the last commit's message to edit; a commit already pushed asks first. Beside it: Sign-off (kept), Author… (the next commit's author, shown under the options until it commits or × clears it) and Commit Message History (Ctrl+M: the messages committed here).
49Commit messageThe Commit Message view below the tree, kept as a draft per workspace, prefilled from git's commit.template (its # lines are the placeholder). Hints under it: a subject or body line over 72 characters, no blank line after the subject. Drag the views' divider to size it.
50Commit and Commit and Push…Ctrl+Enter / Ctrl+Alt+K. One commit per repository with checked files, of exactly those files (git commit --only): anything else staged stays staged. Push… then offers the repositories just committed in.

51Repository stripThe Repository column: a 3px strip in the repository's color, one unbroken strip for a run of its commits, with the name beside it in the row's text color. Narrow, and in File History, only the strip.
52Author discA commit's node: the author's initial (a CJK name: its last character) ringed in the repository's color; a thicker ring is your commit. An avatar covers the initial when the repository's own host has one (linyra.avatars). Merges keep the small hollow dot; hovering a disc of a linear run shows its fold box.
53Branch pillA branch and the remotes whose branch of that name is at the same commit, in one pill (develop | origin); the checked-out branch bold, with ↑/↓ from its upstream; tags their own pill. Click: the branch in the Repo List. Right-click: the Repo List's branch menu (and the AI items while AI is on).
54Commit hover cardOpens when the pointer rests on a row for half a second: author (you, for your commits), relative and absolute time, hash, repository and pills at once; then one git show adds the message and the file and line counts. On the HEAD row: its merge target and Compare. Leaving the row kills the read.
55Operator popupUnder the Search box while it is empty or an operator is being typed: every operator with what it does and its aliases; typing a value suggests authors, branches and tags, repositories or types.
56Whole Word and Match AllBeside Match Case and Regex. Whole Word matches whole words only; Match All needs every message term (git's --all-match), where plain words otherwise match any.
57✨ in the Search boxNatural language: what you type goes to Linyra AI, which writes the operator query back into the box and runs it. Unavailable (with a way to set it up) until AI is configured.
58Ask AI button✨ in the Log header while AI is on: ask Linyra in words; read-only steps run at once, and anything that writes to a repository is listed in one prompt first.
59Change columnFile History only: what each commit did to the file — its letter (A, M, D, R in Source Control's colors) and its lines added and deleted; a rename shows ← the old path.
60Uncommitted changes rowFile History only, above the commits when the file has uncommitted work: opens last commit ↔ working tree. No git process: it comes from the same reads as the Uncommitted side.
62Uncommitted rowOne repository's uncommitted work: its File counts (63) over the Meter (64), the files, the staged tag, its Work branch pill (65) and when a file was last edited.
63File countsFiles by kind as GitLens draws working changes: +new ✎modified −deleted →renamed, each in its Source Control color. The header totals use the same counts across repositories.
64MeterThe share of new, modified and deleted files as one bar, kept under the counts.
65Work branch pillThe repository's checked-out branch: ↑/↓ from its upstream, ☁ when in step, "unpublished" without one, a short hash when detached. Read from the same git status, no extra process.
66Details header and parent linksThe Commit details' pane header (VS Code's look; a click folds it) and each parent's hash, which selects that commit in the Log.
67Explain linkIn the hover card while AI is on: Explain Changes for this commit.
68AI menu itemsExplain, Review and Release Notes on commits; Explain Working Changes, Resolve Conflicts… and Generate Commit Message in the Commit side bar; Explain and Release Notes in Compare. Shown only while linyra.ai.enabled is on; Configure AI… is in the Log's ⋯ menu.

Version 1.4 interaction contract

Exists
Changed-file searchMatches filenames, full paths and rename sources. Enter opens the first match; Escape clears. Matching ancestors remain visible and bulk actions cannot include hidden children.
Layout and fold controlsLog/Changes and Compare support remembered sizes and side-by-side/stacked layouts. Section titles and their blank space do not collapse any view. Folder, commit, duplicate and missing-repository disclosure use their own arrow controls.
Branches in the Repo ListEach repository's Local/Remote/Tags groups, search, favorites and explicitly scoped Git actions; selecting a ref for history does not check it out. Branches Across Repositories… checks out, creates or merges one name in every ticked repository.
Language and themesEnglish and Simplified Chinese follow the editor language. All colors/fonts follow the editor theme, including both high-contrast variants.
